## 误报归因（负样本逐类排查）

评测期间出现过的误报及其根因（均已修复并复测归零）：

| 曾出现的误报 | 归因 | 处理 |
|---|---|---|
| 正常业务 80/443 流量触发"端口扫描"（曾 40 条 FP） | 规则 1000001 端口范围 [1:200] 覆盖了 80；`detection_filter` 按源计数把正常 HTTP 握手计入 | 规则 rev3 排除 22/80 端口段（22/80 有专属规则负责）；复测 FP=0 |
| 低频内网 SSH 被计入爆破计数 | `detection_filter track by_src` 是跨包累计，基线 SSH 与攻击源同 IP 时计数延续 | 数据集把基线终端与攻击源分离；规则语义上 22 端口爆破告警本就只看 22 端口流量 |
| 变种场景告警混入主表统计（假 FP=112） | validator 镜像缓存了旧代码，把"预判型变种"当攻击场景统计 | 重建 validator 镜像；变种独立统计不参与 TP/FP/FN |

当前负样本（3108 包正常业务）**零误报**：DNS 多域名轮询、HTTP 会话、443 握手、低频 SSH 均未触发任何规则。

## 引擎行为发现与 Bug-26 修复

- **常驻 `pcap-file` 回放会跨任务保留 host/阈值状态**：同一慢扫 pcap 曾出现 48、73、26、0 条等不同结果；相同源 IP 的前序 pcap 会污染后续阈值计数，不能用这类结果修改规则预判。
- **修复**：engine-agent 为每个任务串行启动独立 `suricata -r` 进程；常驻 unix-socket 引擎只负责状态与规则热重载。新镜像部署后慢扫独立回放为 0 条，连续两轮 validator 均为 miss，其他场景的 TP/FP/FN 不变。详见 agent-log Bug-26、D-12。
- **libhtp 只解析完整 TCP 会话**：单边 PA 包不产生 http 事件（曾导致 Web 场景 0 告警）。造数据必须带握手/响应/挥手。
- **URI 含未编码空格会被 libhtp 截断**：XSS payload 的 `onerror` 在空格后丢失。场景数据需 URL 编码（也符合真实浏览器行为）。
- **Suricata msg 仅支持可打印 ASCII**：中文描述不入规则体，存 DB 供界面显示。

## 未解决问题与已知缺陷（如实声明）

1. **pcapng 取证回退整文件**：时间/五元组切片只支持经典 pcap；切片时间窗目前固定。
2. **事件串联与聚合配置有限**：S3 gap 固定为 15 分钟，S1 聚合窗口由环境变量配置，未提供界面配置或联动。
3. **检测覆盖范围有限**：当前内置规则覆盖 6 类手法；其他攻击（如 SMB 爆破、TLS 异常）需要增加规则（系统支持自定义规则）。
4. **flow 事件刷新依赖固定等待**：任务完成后等待 3 秒再采集，极端情况下尾部 flow 可能缺失，尚未实现精确 EOF 判定。
5. **原始 eve 归档有限**：轮转只保留 `eve.json.1` 一份，结构化事件已入库，但不长期归档原始 eve。
6. **反向代理客户端 IP**：额外套宿主机反代时，应用可能只看到代理 IP，登录锁定的按 IP 维度会退化；需配置可信代理地址转发。

已修复：取证经典 pcap 切片、C2 心跳时间戳生成、Go 依赖漏洞扫描（govulncheck 0）、跨回放任务的检测状态污染；详情见 README 与 agent-log。
