## 误报归因（负样本逐类排查）

评测期间出现过的误报及其根因（均已修复并复测归零）：

| 曾出现的误报 | 归因 | 处理 |
|---|---|---|
| 正常业务 80/443 流量触发"端口扫描"（曾 40 条 FP） | 规则 1000001 端口范围 [1:200] 覆盖了 80；`detection_filter` 按源计数把正常 HTTP 握手计入 | 规则 rev3 排除 22/80 端口段（22/80 有专属规则负责）；复测 FP=0 |
| 低频内网 SSH 被计入爆破计数 | `detection_filter track by_src` 是跨包累计，基线 SSH 与攻击源同 IP 时计数延续 | 数据集把基线终端与攻击源分离；规则语义上 22 端口爆破告警本就只看 22 端口流量 |
| 变种场景告警混入主表统计（假 FP=112） | validator 镜像缓存了旧代码，把"预判型变种"当攻击场景统计 | 重建 validator 镜像；变种独立统计不参与 TP/FP/FN |

当前负样本（3108 包正常业务）**零误报**：DNS 多域名轮询、HTTP 会话、443 握手、低频 SSH 均未触发任何规则。

## 引擎行为发现（预判修正记录）

- **`detection_filter` 计数状态跨任务持久**：同一攻击源在先后两次回放中计数延续——慢扫变种第一次评测 hit（48 条）、第二次 miss（0 条）。对评测的启示：分布式场景必须做时间窗隔离（30–90s）并给不同场景分配不同源 IP；这也解释了"计数从首个命中包起滑动累计"的真实语义。
- **libhtp 只解析完整 TCP 会话**：单边 PA 包不产生 http 事件（曾导致 Web 场景 0 告警）。造数据必须带握手/响应/挥手。
- **URI 含未编码空格会被 libhtp 截断**：XSS payload 的 `onerror` 在空格后丢失。场景数据需 URL 编码（也符合真实浏览器行为）。
- **Suricata msg 仅支持可打印 ASCII**：中文描述不入规则体，存 DB 供界面显示。

## 未解决问题与已知缺陷（如实声明）

1. **告警取证未做时间/五元组切片**：`GET /alerts/{id}/pcap` 目前回传整段 pcap（响应头声明了过滤条件），逐包过滤切片未实现。
2. **事件串联 gap 与聚合窗口为静态配置**：`AGG_WINDOW_SECONDS` 环境变量 + 15min 固定 gap，未做界面级配置；S3 的 gap 语义（事件切分）也未与 S1 窗口联动。
3. **`govulncheck` 未执行**：宿主机为 32 位 Go 工具链，编译 sqlc/govulncheck 失败；Go 依赖为主流维护库且已用 `go vet` 全绿，npm audit 已清零。列入交付前待办。
4. **评测的盲区**：盲测 pcap 若包含 6 条规则之外的攻击手法（如 SMB 爆破、TLS 异常），将无法检出——当前规则集只覆盖 6 类手法；应对方式是界面内创建自定义规则（已支持，无需改代码）。
5. **`detection_filter` 状态跨任务持久**未做引擎侧隔离，长时运行多任务时同源计数可能互相影响（已在评测中通过源 IP 分配规避）。
6. **flow 事件刷新依赖固定等待**（任务完成后 sleep 3s 再采集），极端情况下尾部 flow 可能缺失；未实现"读到 EOF 且引擎确认完成"的精确判定。
